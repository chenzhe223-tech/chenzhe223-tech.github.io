# KeyPocket V2.0 — 多端加密增量同步

更新：2026-11-02

## 1. 加密模型
登录 Supabase 后，客户端读取当前用户专属随机盐；将 KeyPocket 本地解锁密码经 PBKDF2-HMAC-SHA-256（默认 310,000 次）派生为用户跨设备共享同步密钥。每个业务实体在离开浏览器前再次使用 AES-GCM 加密。

服务端可见：用户 ID、实体类型、实体 ID、版本、设备 ID、更新时间、删除时间和加密 envelope。服务端不应看到 API Key 明文或本地密码。

多设备规则：每台设备必须使用相同 KeyPocket 本地解锁密码。Supabase 账号密码独立于本地解锁密码。

## 2. 增量同步
1. 客户端确保 Supabase Auth 会话有效，过期时使用 refresh token 续期。
2. 登记设备并获取用户盐值。
3. 读取远端逐记录版本。
4. 对本地业务行和回收站墓碑建立本地状态映射。
5. 比较 (version, updated_at, device_id)，将更新版本提交到 keypocket_upsert_sync_item；或下载并在本地解密后应用远端新版本。
6. 完成后生成云端每日/月度加密快照。

RPC 使用 SECURITY INVOKER 并受 RLS 约束。客户端无法用其他用户的 user_id 越权写入。

## 3. 冲突决策
- 时间戳版本更高者胜出。
- 版本相同时比较更新时间，再用 device_id 做确定性平局裁决。
- 记录删除转换成 deleted_at 墓碑；删除不会直接从同步表消失。
- 恢复操作产生新的更新时间，作为新版本提交。
- 永久删除通过加密载荷中的永久删除标记向所有设备传播。

该模型采用确定性的最后写入优先策略，不提供逐字段合并。并发编辑同一记录时，胜出版本会覆盖另一版本；重要数据应保留快照。

## 4. 离线与重试
本地写入独立于远端成功。网络恢复或页面重新可见时触发同步；瞬时失败按退避策略重试。认证失败不无限重试，提示用户重新登录。

## 5. 旧版迁移
第一次 V2 同步会读取旧整库快照；逐条解密合并后写入 V2 表。旧表继续保留，直到真实迁移验收与回滚窗口结束。
