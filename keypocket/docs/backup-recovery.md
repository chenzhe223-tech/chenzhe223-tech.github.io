# KeyPocket V2.0 — 自动备份与恢复

## 当前状态
本地加密快照基础已写入代码；完整恢复验收仍未通过。它不是远程/异地备份。

## 数据兼容
- IndexedDB 仍为 `keypocket-local-v1`，store `vault`，DB version 1。
- API Key 和项目继续使用原 AES-GCM envelope。
- 本地密钥派生继续使用 PBKDF2-HMAC-SHA-256，默认 310,000 次。
- 新快照使用当前解锁的客户端密钥通过原 AES-GCM 函数加密，写入同一 IndexedDB 的 `kp.snapshot.*`。
- 旧版加密备份导入流程仍保留。Replace 导入前尝试生成保护快照并保留快照、元数据与 tombstone。

## 触发和保留
- 常规写入后 850ms 防抖生成快照。
- 删除、恢复、永久删除、替换导入、首次解锁触发保护快照。
- 每日快照检查在用户打开并成功解锁页面后执行；网页关闭时没有后台执行能力。
- 当前目标为最近 30 个不同日期快照；特殊操作快照可能额外存在。
- 尚未实现 12 个月归档策略。

## 安全限制
- 密文内容由客户端 AES-GCM 加密；时间、操作类型及记录数量等索引元数据仍为明文。
- 快照与源密钥库保存在同一浏览器站点存储。清除站点数据、设备丢失或存储损坏可能同时丢失二者。
- 当前没有 Supabase/GitHub 远程加密备份。
- 本地解锁密码与派生密钥不上传。

## 恢复
- 自动备份页面列出本地快照。
- 恢复前尝试创建当前内容保护快照。
- 从选定快照解密记录和项目，并以原加密格式写回。
- 恢复后仍需验收删除记录、回收站 tombstone 和关联关系的一致性。

## 未完成
云端密文备份、12 个月归档、过期回收站自动清理、完整事务回滚/损坏检测和多设备恢复冲突测试。
