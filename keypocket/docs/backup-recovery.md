# KeyPocket 自动备份与误删恢复

最后更新：2026-11-04（UTC+8）

## 单份最新备份策略
- 本地 IndexedDB 使用固定快照 ID `kp.snapshot.latest`；每次自动备份或手动点击“立即更新备份”时，先生成完整 AES-GCM 密文，再以同一 ID 覆盖上一份。
- 新密文写入成功后才清理旧版本化快照；加密或写入失败时保留上一份有效备份。
- 自动备份由密钥/项目保存防抖队列触发，解锁时也刷新最新备份；不再累计每日历史版本。
- 本地备份中心只显示一份“最新完整备份”，支持恢复；恢复前先把当前状态写入同一个保护槽，恢复完成后再将恢复后的状态写回最新备份槽。
- 云端 V2 同步成功后，将完整 records、projects、deleted/tombstone 信息加密后 upsert 为账号级 `milestone/latest` 备份；upsert 成功后再删除该账号其他旧快照。账号级云端只保留一份最新备份，跨设备可恢复。
- 云端清理只针对当前已认证用户的 `keypocket_backup_snapshots` 行，不修改同步记录、设备、认证信息或其他表。
- 独立的“导出加密备份”文件仍是用户主动下载的离线文件，不受自动备份单槽覆盖机制影响。

## 误删恢复
- API Key 与项目采用软删除，不立即清除本地加密原记录。
- 同时写入 encrypted tombstone，包含删除时间、恢复期限、版本和删除实体加密内容。
- 回收站默认 30 天可恢复，支持单条恢复、批量恢复与永久删除。
- 过期 tombstone 会在后续解锁/回收站读取时触发原记录清理并标记 expired。
- 删除/恢复状态应同步到其他设备，防止旧设备把已删除记录重新上传。

## 重要限制
本地快照和主库处于同一浏览器 IndexedDB，因此设备丢失、站点数据清理、浏览器资料损坏时可能同时丢失。云端快照要在成功登录、输入正确同步口令并完成至少一次 V2 同步后才会生成；它不是无需配置的后台备份。
