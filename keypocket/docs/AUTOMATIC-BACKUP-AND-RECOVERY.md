# KeyPocket V2.0 — 自动备份与误删恢复

更新：2026-11-02

## 1. 三类备份必须区分

### 本地自动检查点
每次业务记录写入成功后，经 900ms 防抖更新一份最新的加密检查点。检查点存于当前浏览器 IndexedDB；浏览器站点数据被清理、设备损坏时不能单独提供异地恢复能力。

### 本地历史快照
首次解锁时建立每日、月度快照；删除、恢复、覆盖导入等重要操作前建立里程碑快照。保留策略：每日 30、月度 12、重要操作 24、最新自动检查点 1。

### 云端加密快照
用户登录 Supabase 同步账号且增量同步成功后，按设备创建每日与月度云端快照。服务端只保存客户端加密 envelope。云端快照不可由“本地有一份 IndexedDB 复制”替代。

GitHub App 连接后，本地自动检查点也会尝试将完整加密保险库写入单独私有仓库。

## 2. 保存与备份队列
- 现有 putItem 与 writeItems 入口被 V2 包装，不改变 V1 数据结构。
- 写入成功后排入本地自动检查点；网络可用并已登录时再排入云端同步。
- 云端失败不会回滚或阻断本地保存；状态会显示失败并尝试退避重试。
- 浏览器重新在线、标签页恢复可见时会再次排队同步。
- 本地快照创建失败会显示错误；不能把失败提示当作成功备份。

## 3. 回收站
- API Key、项目和 Skill 的删除先建立操作前快照，再把原加密行移动到回收站。
- 默认保留 30 天；卡片显示删除时间和剩余天数。
- 支持单条恢复、批量恢复和永久删除标记。
- 恢复保留原始记录 ID、密文内容、分类、标签与引用关系。
- 永久删除标记参与多端同步；服务端保留墓碑版本以防旧设备重新上传已删除内容。

## 4. 恢复流程
恢复任一本地、Supabase 或 GitHub 快照前先建立本地安全快照。恢复内容会使用当前时间重置更新时间/版本；同步后作为新版本传播，避免旧版本覆盖恢复动作。

云端/GitHub 恢复依赖用户登录 Supabase 并使用同一 KeyPocket 本地解锁密码派生共享加密密钥。

## 5. 限制
- 本地快照只存在本机 IndexedDB。
- 未登录 Supabase 或同步失败时，不存在可保证的云端副本。
- GitHub App 备份依赖 GitHub App 安装、Worker Secrets 和私有仓库权限。
- 浏览器数据清理前应先确认云端快照或 GitHub 私有仓库备份已实际成功。
- 自动快照在应用运行和解锁期间触发；浏览器彻底关闭期间不会由页面脚本在后台运行。
