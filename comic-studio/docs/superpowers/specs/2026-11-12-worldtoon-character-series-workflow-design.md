# WORLD/TOON 角色、系列与创作流程升级设计

## 意图

把角色档案、全季故事规划、热点选题、画风与视觉素材串成一条清楚的漫画制作路径。创作者可以从热点或主题开始，一次规划系列与角色，再将某一集带入现有创作工作台；角色身份、漫画别名和固定造型能跨作品复用，同时保留作者修改、审批、来源记录和既有制作交付门禁。

## 目标

1. AI 生成漫画剧本后，识别作品中明确标注的男女主角，为其建立可审核的角色档案草稿；重复生成或重试不得重复建档。
2. 保留平台原生 AI 次数额度，增加创作者可选择的 DeepSeek 调用方式。密钥按请求临时使用，提交前展示供应商及潜在费用提示。
3. 建立跨作品的原生角色身份与作品级漫画名映射；角色可被多部独立作品和系列引用，外观及常驻设定可复用，作品内改动按版本显式记录。
4. 提供系列规划流程：先确定主题与系列基本信息，再一次生成可编辑的全季大纲、每集剧情、角色分配、关系发展、固定服装和造型规则；作者确认后，逐集创建现有工作台项目。
5. 重组热点与题材发现入口，让来源类别、内容类型、选题用途和来源日期对应清楚，并突出有代表性的栏目名称。
6. 收紧风格图库的默认占屏面积；桌面和手机都能快速筛选、比较与确认风格。
7. 将视觉参考按人物、服装、空间、道具、配饰、光线/构图等用途组织，只在适合的角色、集数、场景或画格应用，并在交付资料中保留来源与许可。

## 不做的事

- 不自动发布作品，也不替作者完成角色、剧情、事实、图片或版权审批。
- 不抓取小说或短剧全文，不大量复现受保护作品的原文或具体表达；允许公共领域内容在核对版本与地区版权后使用，现代作品仅做抽象主题灵感或在有授权时改编。
- 不把 AI 推荐分数、缓存快照或来源数量描述成经核实的实时热度。
- 不把视觉参考图默认为漫画成品，不将一项素材自动套用到所有作品。
- 不迁移或清空现有工作区，不改动现有 GitHub QA、作者审批、私有交付与 WorkBuddy 发布回执门禁。

## 当前实现与约束

- 平台是静态前端加 Cloudflare Worker，项目、选题及角色资料以本地优先工作区保存，并可选择同步至现有 Supabase 工作区；因此本次使用可向前兼容的增量字段，不重建云端数据模型。
- `data.characters` 已保存角色档案。现有角色 AI 已通过 `/api/ai/characters` 提供 DeepSeek/平台免费模型调用，并有登录和使用次数限制。需要在保留该配额路径的同时增加可选 DeepSeek 路径，不能把 API 密钥写入作品、备份或 localStorage。
- 项目中存在创意导演角色表 `creativeDirection.cast`、旧字段 `characters`、系列字段 `seriesId` / `seriesBible`。续章已有造型锁定逻辑，规划数据要兼容这些字段，不能静默覆盖旧项目。
- 系列、热点、视觉素材已有入口和数据：`editorial-series.json`、新闻及文学等分类、`visualReferences` 及 CC0 馆藏来源。本次扩充其结构和筛选/应用体验，不凭空制造素材或来源。
- AI 生成结果始终为可编辑草稿。角色归档、系列锁定和每集创建都应有清楚的作者确认点；图片与公开发表仍遵循当前生产、QA、作者审批流程。

## 方案比较与选择

### 方案 1：沿用现有工作区做增量升级（已选）

新增兼容字段和界面流程，沿用当前本地优先数据、Supabase 手动同步、Cloudflare Worker AI 代理、现有漫画工作台与 GitHub QA。优点是保留资料、缩小迁移范围；不足是跨设备变更仍沿用现有工作区的同步方式。

### 方案 2：迁移为中心化角色／系列数据库

建立服务器关系表和新的同步协议，所有角色、别名、系列、分集和素材关联由服务端维护。跨设备关联更统一，但会牵涉账户、迁移、回滚和旧备份兼容，扩大数据风险和改造范围；本次不采用。

## 已选数据规则

采用“当前创作者工作区内可复用的原生角色身份 + 作品级漫画名 + 系列共享角色圣经”。此处的“可复用”仅指同一创作者当前本地工作区及其已登录同步工作区内的作品，不跨账号共享或搜索其他创作者的角色资料。原生身份以不可变 `characterId` 标识；名字不能单独作为去重依据。每部漫画可为同一身份设定自己的漫画名，系列章节可以继承角色与造型，也可经作者确认建立新版本。旧版角色不具备稳定身份时，以增量字段补齐并允许作者手动关联，不自动合并同名角色。

## 体验与流程

### 1. 角色档案

- 档案页分为“角色档案”和“本作品角色”视图；角色档案限当前创作者工作区可见，旧档案继续显示并可编辑。
- AI 编剧返回的角色结构包含明确的角色定位。只有明确标记为男女主角且角色字段完整时，自动创建档案草稿；不确定性写入待确认状态，禁止根据名字或外貌猜测性别/主角身份。
- 按项目和来源内容生成稳定的幂等键，优先复用已绑定的角色 ID；发生匹配冲突时让作者选择“复用档案 / 创建新身份”。
- 档案含原生名、项目漫画名映射、身份/设定、性格、固定外观、基础服装、可选服装版本、代表色、识别特征、参考图许可和来源。漫画名或衣着可按作品/集数变化，角色核心身份不会被覆盖。
- DeepSeek 为 AI 角色设计表单中的可选生成通道。原生 AI 仍用现有登录、配额和模型；DeepSeek Key 仅在用户当次确认后发往本站固定 Worker 代理与 DeepSeek API。界面清楚说明计费、调用范围和密钥不会留存；平台不提供“无限免费调用”承诺。

### 2. 系列策划与连续性

- 从题材发现、已有作品或工作台进入“规划漫画系列”，明确选择系列主题和原创/授权改编路径。
- 设置系列名、核心主题、目标读者、集数（可手动指定，也可先由 AI 建议）、单集画格目标和角色人数范围；AI 一次返回全季结构化计划，包括总弧线、每集摘要/冲突/悬念、人物进入退出与成长、每集服装/道具/场景，以及贯穿全季的视觉规则。
- 角色圣经至少保存角色身份 ID、各作品名、关系、固定外貌/体型、常规服装、识别物、可变化的服装场合与禁止变化项。系列圣经另存世界观、画风锁、时间顺序和延续摘要。
- 全季计划以草稿显示，作者可逐集修改并一次确认锁定。只有确认后才创建各集工作台项目；创建过程可重试且不生成重复集数。每集继承计划中的角色 ID、别名、剧情与衣着规则。
- 续集制作后更新“上一集回顾/未解决线索”，但不静默改写已锁定集纲；重新规划生成带版本号的提案，作者确认后才替换后续计划。
- 系列作品仍逐集走当前人工审阅、真实成品 QA、作者审批和发表回执链路。

### 3. 热点与题材发现

- 入口以明确的内容类型导航组织：全球热点、红果/网剧线索、网络小说/世界名著、历史故事、科技与学术等。分类名准确描述来源与内容，不互相暗示来源身份。
- 页面采用“选来源/题材 → 搜索并核对作品身份和日期 → 查看可追溯候选 → 选择剧情弧线或创作主题 → 进入系列规划/单篇工作台”的顺序。
- 热点新闻、文学作品、短剧节目和长期题材分开展示；卡片显示来源名、来源日期、检索/快照时间、作品身份可信状态、版权状态与推荐理由。快照与规则评分明确标注，不伪造实时热度。
- 选题摘要与卡片标签必须来自同一候选记录；来源失败、身份不确定、空结果和版权待核查均给出对应提示。

### 4. 风格选择器

- 桌面默认使用紧凑筛选栏和较小卡片；手机默认单列或横向可滑的类别标签，避免一次铺满 25 个大卡片。
- 搜索、类别和当前选中风格始终可见；展开时才查看完整示例、说明和禁用项。选中确认后风格进入项目/系列圣经。
- 不删除现有风格、示意图、元数据和移动样式契约；图片仍明确标注为风格参考而不是 AI 成品预览。

### 5. 视觉素材

- 统一素材类型：人物形象、服装/穿衣风格、空间/布景、道具/配饰、光线/构图。每条保留类型、适用场景、来源 URL、作者、许可/权利状态、素材日期与原始图片引用。
- 在角色档案、系列圣经、分集规划和具体画格分别提供相关素材检索与“应用到”动作。角色素材关联角色；服装关联角色与场合/集数；空间关联场景/画格；道具和装饰关联具体镜头。用户可移除或更换，不默认全作品套用。
- 只有 CC0、自有或经授权素材能进入生产参考包；其他资料只显示可访问的来源链接或研究说明。参考素材作为生成提示/审核参考，不复制到交付成品；在生产包中记录素材的应用对象与来源链。

## 数据兼容与隐私

- 为角色引用、别名、系列计划和素材关联使用带版本的增量字段；旧字段继续读取。导入、导出、备份和云同步保留新旧资料，不丢弃未知字段。角色身份数据仍受当前工作区及 Supabase 用户级 RLS 隔离，不增加跨用户目录或公开检索。
- AI 返回须做结构与长度校验；生成内容追加为草稿，未确认前不改写已审核剧本或系列锁定数据。
- DeepSeek 密钥采用短时前端内存状态，写入请求体仅发往本站 Worker；Worker 固定供应商 URL、限制输入大小/调用频率、清理错误信息和日志中的敏感值。默认原生 AI，调用第三方前提示可能计费。
- 不变更 Supabase 私有存储规则、已有用户数据、GitHub 仓库内容、审批签名或 WorkBuddy 队列协议，除非为兼容新增的系列/角色元数据确有必要并保持旧客户端可读。

## 成功条件

- 对含明确男/女主角的 AI 剧本，可生成可编辑档案草稿；重复操作不重复建档，作者能确认或更正身份。
- 一个原生角色可关联多个漫画身份/别名和多个系列章节；旧角色、旧作品和旧备份仍可打开。
- 创建系列后，可看到完整可编辑的全季计划；确认后每集正确进入同一工作台，并继承固定角色 ID、服装规则、关系与剧情连续信息。
- 热点/题材内容按来源与类型进入正确栏目，作品摘要、来源和日期对应；搜索失败与空结果明确。
- 桌面/手机风格选择器易于浏览，且保留全部风格选项。
- 视觉素材能按类型搜到并应用于对应角色/服装/场景/画格；不合许可规则的素材不能进入生产参考包。
- 现有作品、人物、系列、作者审阅和正式发表门禁继续有效。

## 仍由实现者决定的细节

- 在既有 `data.characters` 与 `creativeDirection.cast` 中如何引入最少量的 `characterId` 引用、别名表和服装版本字段；必须保留旧字段并从旧结构安全读取。
- “角色档案”已明确为当前创作者工作区范围，不跨账号共享；实现者沿用已有用户级云端隔离。
- DeepSeek Key 输入控件在生成表单中的最小布局与明确费用提示文案；不落盘、不打印、不回显完整 Key。
- 现有视觉素材源中哪些类型已有可靠可用数据，缺少的类型先提供可追溯的用户上传/手动登记入口；不得伪造 CC0 馆藏。
- 热点栏目命名和页面信息层级以现有素材类别为准，命名可由实现者收敛，但不可把通用网络搜索称作红果官方热度。
