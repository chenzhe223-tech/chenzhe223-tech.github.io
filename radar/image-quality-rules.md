# DAVYLAB Radar｜新闻图片质量与来源约束 V1

生效：2026-11-07。适用：每日正式简报网页、正文新闻卡、1200×1800 网站海报；已取消的微信六图不恢复。

## 核心决策

1. **有图不等于合格。** 官方新闻原图、产品截图优先；无可靠、完整图像时，使用与新闻事实绑定的 DAVYLAB **信息卡**，不要强行用通用图库填满。
2. **图片不得冒充事实。** Unsplash / Openverse / 主题示意图一律不作为具体新闻的现场摄影展示；品牌信息卡必须包含“非新闻现场”。数据库保留原图来源、许可及 SHA256 以供追溯。
3. **满铺优先、主体保护。** 普通新闻原图使用 cover 满铺；人像全身、机器人及重要技术界面用原图模糊背景满铺 + 完整前景 contain，严禁空白灰边和截掉人物头部、脚部或重要界面。低质量、无关图片才转信息卡。
4. **不得在浏览器请求失败后临时替换为另一张未检验图库图。** 发生加载错误时显示来源信息卡。
5. **不声称没有执行的语义识别。** 当前 V1 为确定性的来源类型、像素、宽高比及版权标记检查；没有实测图像语义 AI、OCR、脸部检测、页面截图内容逐项比对。语义不明的图库素材保守转为信息卡，而非伪造相似度高分。

## 真实实现

- 选图及去重：`radar/scripts/news_image_match.py`，优先原文和发布方素材。它提供的主题图库素材会在展示阶段被抑制。
- SHA256 / pHash：`radar/scripts/quality_gate.py`（保留以前本周禁重复及所有新闻 P0）。
- 像素质量：`radar/scripts/image_visual_quality.py`（`2026-11-08.1`），依照确切校验过的字节检查：
  - 最短边 <230 px 或像素总数 <100000，转信息卡。
  - 宽高比 >4.5 或 <0.23 且难以合理展示时，转信息卡。
  - 竖版人像或主体敏感的机器人/技术图，不转信息卡：保留全主体，并让**同一张图**的模糊背景铺满全部区域。
  - 灰度标准差 <8（近乎均匀空白），转信息卡。
  - 主题图库图、无确认新闻关联的插画：转信息卡。
  - 无法解析或与已验 SHA256 不一致：P0 阻断并尝试下一候选，不伪造成功。
- 数据字段：`image_visual_quality.policy_version`、`display_mode`、`crop_mode`、`crop_policy`、`reasons`、`width`、`height`、`aspect_ratio`、`luminance_stddev`、`content_digest_sha256`、`semantic_match_model_verified=false`。汇总记录进入 `test-results/radar/news-image-quality-gate.json` 的 `images.visual_decisions`。
- 网站：`radar/daily/index.html`，普通合格图 `cover` 满铺；特殊主体图由 `radarImageLoaded` 选择完整前景 + 同图虚化背景。无关、低质、失效图才转信息卡。禁止随机 Unsplash 兜底。
- 海报：`radar/scripts/generate_poster.py`，相同策略；验收元数据区分 `verified_photo` 与 `info_card`，并明确记录原图校验摘要和卡片像素摘要。
- 生产：`.github/workflows/pages.yml` 必须在 QA 与最终图、QR、移动端测试全 PASS 后才能提交，不得绕过或覆盖上一有效版。视觉策略版本变化会触发正式重新验收。

## 进阶项（不得标记为已完成）

真实图像主体检测、语义相似度模型与可追溯的视觉模型评分、识别内部水印及截图文字、用户一键换图审核台尚未完成。这些需要额外模型/运行依赖和真实图片样本验收，不能仅凭元数据声称合格。V1 的保守信息卡策略先消除明显乱配图。

## 验收证据

执行 `python -m unittest radar.scripts.test_image_visual_quality radar.scripts.test_quality_gate radar.scripts.test_poster_generation -v`，再执行 `node scripts/qa-radar.cjs`（需 Playwright / 本地静态服务），最终确认 GitHub Actions 的数据、主海报二维码、线上图像及浏览器检查均 PASS。

视觉信息卡不能当作新闻图片新闻现场。不得恢复已取消的 900×1200 微信六图与专题海报。

## 新闻配图三级规则（2026-11-08 确认）

**规则 1｜新闻源配图优先。** 先核对来源文章、官方博客或发布稿自带的 RSS/OG/Twitter 图片；过滤站点 Logo、通用图库、坏链及过低分辨率图片。若第一候选不合格，继续尝试同一原文的其他候选，不能只取第一张。

**规则 2｜新闻源无合格图则按标题搜索。** 以新闻原始标题、准确翻译、明确项目/产品实体为查询条件，优先搜索拥有可追溯来源页面、明确可复用许可且与标题有足够实体及词汇重叠的图片；禁止拿无关植物/人物/风景配新闻。搜索命中的图明确标注“搜索配图 · 非新闻现场”，保留出处、作者、许可证和相关性分数。搜索结果缺少可信授权或主题证据时，不得使用；最终使用信息卡，而不是伪造现场照片。检索模块保持限时、可恢复，避免整份日报被单个图源拖死。

**规则 3｜人物与主体完整。** 含人脸、人物全身、机器人及产品演示的图片优先保全完整主体，禁止仅剩半张脸、半个头或明显截断身体。网页/海报默认满铺；对人物和长图，采用原图完整前景＋同一图像虚化满铺背景。已有 OpenCV 时自动检测人脸作为主体保护信号，未检测到不等于无人脸。原始文件本身已不完整或分辨率太差，不能通过填充恢复内容：需改用其他合格图片或已标识的信息卡，不得宣称修复了原图内容。

三项规则同时作用于简报网页、正式 1200×1800 海报和日常自动化；不恢复已取消的微信六图。素材合规、来源去重、视觉锁定、二维码等 P0 门禁保持不变。

## 2026-11-08 补充：取消重复的抽象图标式网页配图

用户明确拒绝批量重复的 `MODEL / COMPUTE / H200 / MEDIA` 蓝色图标模板。**网页新闻卡**不得使用程序化通用主题 SVG 充当新闻图片；原图、授权可复用的相关网络图片均不可用时，新闻保持文字、标题、来源与链接完整，**不渲染图片区域**，而不是填入相同的视觉模板或未经查证的图库照片。图片加载异常也采取同样逻辑。正式海报仍须单独遵循其固定信息层级和 P0 检查，不因本规则取消海报本身。

配图去重必须跨当日精选与中国区新闻执行：不同新闻不得共用同一个实际图片资源（包括改尺寸链接），验证程序同时保留 SHA256/pHash 周内查重。若一张图无法通过来源、版权、相关性或重复检查，不得仅因缺图而降低验收标准。
