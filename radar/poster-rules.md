# DAVYLAB AI 前沿简报海报生成与发布规则

版本：2026-11-03
权威实现：radar/scripts/poster_style.py、generate_poster.py、verify_poster.py 与 .github/workflows/pages.yml。

本规则适用于每日简报的海报生成、检查与发布。文档、程序和工作流必须执行同一套规则；发生冲突时必须修正代码和自动化测试，不能只改说明。

## 1. 视觉基准与尺寸（P0）
- 唯一已批准视觉参考为用户明确认可的 2026-10-31 正式海报：截图 SHA256 为 7ec1b618ff78cf40b8a46c346aff23a80f6dfe11b83b30485546cd5483e406bd（1086×1448 JPEG）；网站生产基准文件为 radar/posters/2026-10-31.png（1200×1800 PNG）。两者是不同渠道的基准文件，不得混淆。其他历史海报仅作风格实现记录，不构成新增批准参考。
- 默认画布为纵向 1200 × 1800 像素（2:3），与现有生成器和二维码验收标准一致。
- 每张海报呈现 DAVYLAB、AI FRONTIER BRIEF、中文主标题、真实日期、当期主题、五条精选新闻、实用 Skill、行动洞察、真实二维码及正式简报 URL。
- 主色为深海军蓝、暖白，少量科技蓝或橙色强调；避免廉价渐变、常规模板拼卡、拥挤排版和过度装饰。
- 使用真实可用的中文字体；图像生成模型只负责视觉素材，不生成新闻文字、数字、品牌标识或二维码。
- 每张海报是完整独立的 PNG，不得拼图或把两种风格放在同一画布。
- 参考图中的旧日期、旧新闻、历史数据和二维码不得作为当日事实沿用。

## 2. 两种风格按 ISO 周交替（P0）
按周切换，不按日切换。每天仅生成当周指定的一张风格；重试不能改变风格。
- 深色几何科技编辑风：geometric-navy。顶部必须使用深海军蓝头图、暖橙色日轮和分层几何山峦剪影；正文为暖白底色，采用深海军蓝文字、克制橙色强调、三张主新闻卡片 + 两张补充卡片、Skill 推荐区和右侧独立二维码。该组合是 ISO 周算法定义的 geometric-navy 风格变体，不构成第二份批准参考；品牌语言、信息层级与质量标准仍以 2026-10-31 唯一批准参考为准。
- 暖白山峰科技杂志风：mountain-editorial。暖白编辑版式，以真实山峰/云海摄影作为主视觉；顶部使用超大中文标题与蓝色日期，正文严格采用五栏等宽新闻网格（标题、摘要、图片和来源按固定节奏排列），下方为今日观察横幅、左侧 Skill 推荐卡、右侧独立二维码框及品牌页脚。与 geometric-navy 的几何插画山峦头图明确区分。
- 唯一算法位于 radar/scripts/poster_style.py::poster_style_metadata：固定锚点为 2025-12-29（ISO 2026-W01 的周一），按目标日期所在周的周一与锚点相差的完整周数计算连续周索引。偶数索引使用 geometric-navy，奇数索引使用 mountain-editorial，保证跨 ISO 年份仍每周切换。
- 生成器、定时预检、二维码验证和部署后验收必须共享同一算法；禁止另外使用日序号奇偶判断。
- 海报和验收记录必须包括 iso_year、iso_week、style_cycle_index、style_cycle、design_variant、template_version 及与该风格一致的 design 标识。geometric-navy 的 design 必须为 geometric-navy；mountain-editorial 的 design 必须为 mountain-editorial。
- 示例：2026-10-23 属于 ISO 2026-W43，使用 geometric-navy；2026-10-26 开始的 ISO 2026-W44 使用 mountain-editorial。
- 自动测试覆盖同一周风格一致、相邻周风格不同、重试确定，以及 ISO 第 53 周到下一 ISO 年第 1 周仍交替。

## 3. 新闻事实、图片与 Skill 推荐（P0）
- 每日先生成并验证正式简报数据，再生成海报。海报日期必须与 radar/data/latest.json、当天归档及线上正式内容一致。
- 默认展示五条经核验新闻和一个实用 Skill；标题、摘要、日期、重要数字和来源必须来自正式数据及可追溯原始来源。
- 原文链接必须是可访问的 HTTPS 地址。不能核验的消息不得作为确定事实发布。
- 新闻图像必须与对应新闻可验证地相关。优先采用来源页或可靠图库中可追踪的匹配图片。若使用 Unsplash 等主题备用图，必须在图面显著标注「主题插画 · 非新闻现场」，不能误导读者把它当成事件照片。
- 缺少相关照片时可使用清楚标注的主题插画，不得用无关图库照片冒充新闻现场、产品或人物。
- Skill 项目、仓库地址、功能描述及可见统计均须有实际依据；检查近期推荐记录，尽量避免重复。
- 不得为了填满版面编造新闻、数字、企业标识、人物、星标、下载量、许可证或产品功能。

## 4. 真实二维码与固定入口（P0）
正式二维码 URL 必须逐字符等于：
https://chenzhe223-tech.github.io/radar/daily/
- 使用标准二维码库在本地生成；禁止仿画、占位符、远程临时二维码或虚构链接。
- 嵌入最终 PNG 后，再从完整图片中解码，并将结果与正式 URL 完整字符串比较。
- 检查二维码尺寸、右侧独立位置、对比度、白色静区及是否被裁切或遮挡。
- 实际请求正式网页，记录 HTTP 状态和最终跳转 URL。
- 写入 radar/posters/YYYY-MM-DD.qr-verification.json 和 radar/posters/latest.qr-verification.json，记录日期、风格元数据、图像路径、解码值、目标 URL 和逐项结果。
- 发布后重新下载线上日期海报和 latest.png 并再解码，确认线上文件及数据属于当天。
- 程序解码不等于真实手机摄像头扫码。未完成实机测试时必须标记尚未进行实机扫码。

## 5. 发布阻断与恢复
- 任一 P0 检查失败，禁止提交失败的海报或二维码报告覆盖有效线上版本。
- 每次运行先读取 main 最新版本和真实日志；当日报告、当周风格海报及 PASS 校验全部匹配时才能安全跳过。
- 新闻采集、AI 编辑、图片匹配、渲染、二维码验收、Git 提交、Pages 部署和线上检查必须具备可追溯运行记录。
- 北京时间 07:30 是目标发布时间而非精确保证；保留补救运行。失败必须诊断、修复并重新测试。
- 保留上一份有效公开版本；严禁发布半成品。

## 7. 每次执行顺序
1. 读取最新 main、当日数据、来源、历史记录和失败日志。
2. 采集并核验今天新闻，运行数据契约测试。
3. 使用共享算法确定当周风格。
4. 按参考图生成当周风格的一张完整海报。
5. 生成真实二维码，验证最终图像、来源和排版。
6. 更新当天归档、历史索引、海报、清单与二维码报告。
7. 提交正确仓库并等待 Pages 部署。
8. 重新检查线上数据与图片，核对日期、风格、二维码和历史归档。
9. 发布朋友圈短文案及正式链接，并如实说明未完成测试。

## 8. 社交图片生产状态与文字文案（2026-11-03 更新）

**当前生产决策：微信公众号六图已停用。** 用户已取消每日「1 张主海报 + 5 张独立专题配图」社交图片包。

- 每日只生成网站正式主海报 `radar/posters/YYYY-MM-DD.png`，规格固定为 **1200 × 1800 px、PNG**，并按第 1–7 节完成二维码、视觉和线上发布验收。
- 不得生成、上传、归档或验收 900 × 1200 的微信六图、五张独立专题配图或社交图片 ZIP；这些项目也不得成为正式网页发布的 P0 门禁。
- 保留文字版贴图短文案和朋友圈推广文案。文案必须与当日正式简报数据、新闻来源和 Skill 完全一致。
- 只有用户今后明确重新提出社交图片制作要求，才可重新规划并启用该生产链路；不得由定时任务或旧规则自动恢复。

### 8.1 每日贴图短文案：固定表达结构（保留）

本条专指随网站主海报发布、供朋友圈或公众号文字配图说明直接复制使用的「贴图短文案」。每日必须单独交付一份短文案成稿；不自动生成完整公众号长文。

**固定结构与顺序：**

1. **观点式主标题**：用一句自然、有判断力、容易记住的话概括当天 AI 新闻的共同趋势。优先采用口语化表达，例如「AI 不只要更强，还得真能干活」。标题必须由当天真实新闻支撑，不得为了吸引眼球夸大。
2. **背景对比开场**：用 2–3 句短句建立问题意识。可采用「过去两年，我们习惯用参数、榜单、发布会衡量 AI。现在问题变了：它能不能真的干活？」这一表达逻辑；具体措辞须随当天主题调整，不得机械照抄。
3. **当日新闻引导句**：用一句短句引出当天精选动态，明确真实日期或时间范围，例如「10 月 30 日前后的几条动态，都指向同一个方向 👇」。
4. **新闻/动态速览**：选择当天最值得关注的 3–5 条新闻或工具动态。每条使用「相关 Emoji + 新闻主题/项目名 + 事实与实际意义」结构，正文控制在 2–3 句，语言通俗、短段落、手机阅读友好。准确保留事实边界、时间、数字和限定条件；企业或管理层说法须明确归属；不得将推测写成事实。新闻不足时按真实可核验数量发布，不得凑数。
5. **DAVYLAB 观察**：固定使用「💡 DAVYLAB 观察」作为小标题，以 2–3 句提炼多条新闻背后的共同趋势，并说明对企业、从业者或普通人的实际意义。此处属于 DAVYLAB 分析，不得伪装成新闻事实。
6. **互动问题**：以「❓」开头提出一个与当天主题直接相关的问题；可给出 A/B/C/D 等简短选项，选项须具体、互斥或易于理解，并邀请读者在评论区分享真实场景。
7. **品牌署名与标签**：以「作者：DAVYLAB｜让可能发生」收尾，随后添加 3–5 个与当日内容相关的话题标签，例如 #AI #人工智能 #AI工具 #职场效率。

**语气与编辑要求：**
- 自然、直接、有判断力，像懂行业的人向朋友解释新变化；不是新闻播报腔、研究报告腔或机械摘要。
- 适量使用 Emoji 作为视觉锚点，不堆砌符号；每条新闻保持短段落，适合手机快速浏览。
- 主标题、开场、新闻顺序、DAVYLAB 观察和互动选项应形成一条清晰逻辑：提出变化 → 用新闻举证 → 提炼趋势 → 邀请读者联系自身场景。
- 新闻精选以当天正式简报为唯一内容基准；新闻标题、事实、数字、来源、Skill 名称和链接必须与正式简报、网站主海报及文字文案一致，不得跨日期混用。
- Skill 推荐须核验仓库、官网、许可证和能力说明。若未实际安装或测试，必须在对应条目中明确披露，例如：「已核验仓库和官网，未实测安装，使用请自行评估。」实际测试状态不同则按事实表述。
- 不将完整公众号长文直接压缩粘贴成贴图短文案；贴图短文案应独立、精炼、可直接复制发布。

**每日贴图短文案验收：**
- [ ] 有观点式主标题，且由当天事实支撑。
- [ ] 有背景对比开场和真实日期引导句。
- [ ] 精选 3–5 条新闻/动态，每条均为 Emoji + 主题 + 事实/意义。
- [ ] 包含「💡 DAVYLAB 观察」，且清楚区分事实与分析。
- [ ] 包含「❓」互动问题及贴合主题的选项/评论邀请。
- [ ] 以指定品牌署名收尾，并含 3–5 个相关标签。
- [ ] 所有新闻与 Skill 内容均可追溯，并与当日正式简报及网站主海报一致。
- [ ] 文案语气自然、短段落、手机阅读友好，可直接复制发布。

## 9. Machine-enforced visual lock (V3.0)
The approved 2026-10-31 user-confirmed mountain-editorial poster is the active visual baseline. Machine-readable controls live in `radar/config/`:
- `baseline.json`: approval identity, reference screenshot SHA-256, production reference path and channel distinction.
- `style-lock.json`: deterministic ISO-week style selection and retry lock.
- `layout-spec.json`: website poster dimensions and fixed region order; the legacy WeChat social-pack block is inactive and not used by daily production.
- `typography.json`: CJK font policy; production rendering must fail closed if a supported Chinese font is unavailable.
- `color-tokens.json`: named mountain-editorial palette.
- `qa-rules.json`: fail-closed checks and three-round maximum repair policy.
- `poster-feedback-log.md`: approved feedback and regression history.

The runtime gate `radar/scripts/visual_lock.py::validate_visual_lock` is called by `generate_poster.py` before rendering. It verifies configuration presence, the ISO-week style, website canvas dimensions, immutable QR destination, baseline identity, typography policy and repair limit. Any missing or inconsistent configuration blocks rendering. The website poster remains 1200×1800. WeChat six-image production is disabled as of 2026-11-03 and is not generated, uploaded, or required by the daily publish gate.

Any future change to the approved baseline requires explicit user approval. A newly generated poster, by itself, never becomes a baseline.


## 10. 新闻配图相关性与信息可信度门禁（P0）

- 仅当图片候选的主题相关性分数达到 `radar/config/qa-rules.json` 中的 `image_relevance.minimum_score`（当前 0.35）时，才允许使用 Openverse、Wikimedia 或 Web 搜索图片。
- 低于阈值时必须放弃该候选，改用与新闻主题匹配的主题配图；不得因为图片 URL 可访问就视为相关。
- 主题配图、搜索配图必须在页面与海报上明确标注“主题配图 · 非新闻现场”，不得暗示为真实新闻现场照片。
- “智能体 / agent”默认指软件代理，不得自动映射为实体机器人；只有机器人、具身智能、人形机器人等明确语义才使用机器人素材。
- 低置信度新闻必须在摘要中注明来源归属及“尚未独立验证”，企业自报分数、性能或预测不得写成独立验证事实。
- Skill 必须展示许可证、官方项目主页、实际文件证据、适用 Agent/平台兼容性，以及未实测安装或未完成安全审计的限制。
- 每日不生成或验收微信六图包。文字贴图短文案必须与 `radar/data/latest.json` 的日期、五条新闻、来源和 Skill 一致。
- “首次、首个、最高、最大、纪录”等表述必须同时给出可核实的指标口径与日期/范围；研究原型、非正式产品、未量产状态必须保留；基准分数、性能提升和预测必须注明由谁测得或披露。
- DAVYLAB 趋势判断必须明确标记为分析观点，并在正式数据中提供至少 3 条可点击的 `source_basis` 新闻来源；网页展示依据来源，贴图文案说明这是基于本期公开来源的综合判断。
- 每日不生成五张独立专题配图；五条精选新闻、Skill 和来源继续完整展示在网站正式海报与文字贴图文案中。

## 11. 新闻图片展示安全与内容完整性（2026-11-07 增量）

优先使用可信的新闻原图、官方产品图和技术界面图；**不以“有图片”为合格标准**。图像检验和展示规则详见 [image-quality-rules.md](./image-quality-rules.md)。

- 视频缩略图、人物、UI、产品示意在新闻卡片/海报一律保留完整主体，不采用无保护居中截取。源图不适合卡片形状时显示已注明的 DAVYLAB 新闻信息卡。
- Unsplash、Openverse 等图库的通用风景、人像、植物、办公室照片，即使可下载、可用于某个话题，也不得冒充具体事件的照片；选图失败、素材比例不合适、图片太小或失效时，使用包含可追溯新闻标题和来源的品牌信息卡，不使用未校验的随机备用照片。
- `image_visual_quality` 根据已核验图像字节记录像素、比例、画面对比度与转换原因，不伪称通过语义模型检测。图片缺失、损坏、内容校验不符仍维持 P0；未进行的主体 AI 识别不得宣称通过。
- `image_display_mode`、`image_visual_quality` 和海报 `rendered_visual_type` 必须与真实展示一致。海报信息卡的像素摘要与外部来源图片摘要分别记录，不得混同。网页浏览器测试必须检查主题图库被抑制、照片为完整展示（contain）。
- 不新增微信六图和每日社交专题图片。现有 1200×1800 正式海报、固定二维码及 ISO 周风格完全保留。


### 2026-11-08 用户确认的配图优先级（强制）

1. **先新闻源**：优先原文文章/官方发布的配图，过滤无关图、站点 Logo、坏链；多候选按来源可信、主题相符、主体完整选用。
2. **再标题搜索**：新闻源没有合格图，依据新闻标题、实体及产品关键词进行限时检索；仅采用来源可追溯、许可可复用、相关性合格的图片。搜索图必须标注“搜索配图 · 非新闻现场”并保留作者和授权记录，不可作为新闻现场图。
3. **完整人像**：出现人物、人脸、机器人全身时不得只显示半个头或半张脸、明显截断人物身体。普通图片满铺；人物/重要界面采用同图虚化背景满铺并保留完整前景。原图本身缺失人物部位不能凭裁切修复，应更换合格来源或显示合规信息卡。

执行详见 `radar/image-quality-rules.md`，既有二维码、画布、来源、去重、P0 和不制作微信六图的规则保持不变。
