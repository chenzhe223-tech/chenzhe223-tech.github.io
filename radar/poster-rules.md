# DAVYLAB AI 前沿简报海报生成与发布规则

版本：2026-10-21

本规则适用于 DAVYLAB AI 前沿简报的每日海报生成、检查与发布。后续执行必须逐项遵守，不得以“生成成功”代替质量验收。

## 1. 独立图片交付（P0）
- 用户要求生成两张海报时，必须交付 **两个独立图片文件**。
- 两张海报必须分别发起独立的图像生成任务；禁止拼接、拼图、左右并排、上下组合、双联画或将两张海报放在同一张画布中。
- 每个文件必须是一张完整海报，可独立保存、转发和发布。
- 建议画布尺寸为 1080 × 1350（4:5）；如平台另有要求，以明确要求为准。
- 交付前核对文件数量、每张图片的完整性与可读性。若只有一张拼图，视为未完成，必须重新生成。

## 2. 既定视觉风格
- 以用户提供的两张参考海报为视觉基准：高级科技杂志与编辑设计结合，图文并貌，层级清晰，留白克制。
- 统一 DAVYLAB 品牌标识、字体层级、间距、细节与版式语言。
- 配色以深海军蓝、暖白为主，少量科技蓝或橙色作强调；避免杂乱高饱和、廉价渐变和普通文字卡片拼排。
- 两套风格按日交替使用：
  1. 深色科技风：具有质感的主视觉、醒目的日期和本期核心议题。
  2. 暖白编辑风：杂志式信息排版，突出新闻图片、摘要、观察与推荐。
- 两张海报分别呈现完整设计，不是把两套风格放在同一张图中。
- 第二张海报对应栏目标题固定使用 **「今日推荐」**，不得写成「今日观察」。

## 3. 当日内容真实性与关联性（P0）
- 生成前先读取当日正式简报数据，再确定主题、标题、摘要、图片和版式。
- 默认呈现当日简报的 **五条精选新闻 + 每日 Skill 推荐**。
- 新闻标题、数字、摘要、日期、来源与原文链接必须来自当日简报数据及可核对的原始来源；严禁编造、猜测、过时挪用或为排版填充未经核实的信息。
- 每条新闻配图必须与对应新闻真实关联。优先使用来源页中可确认的新闻图片；不得用无关的装饰图冒充新闻现场或产品图片。
- 每日 Skill 必须使用真实项目名称、有效项目链接及有依据的描述；按日轮换，避免连续重复推荐（若数据不足，应明确说明，不得伪造轮换）。
- 海报内容必须与线上对应日期的正式简报一致。若当日数据未更新、来源缺失或内容无法核验，先排查或标注，不能擅自补写。
- 可包含简报核心价值和「好点子，收进念头盒」的理念，但不得挤压主要新闻信息。

## 4. 二维码规则（P0）
- 每张海报必须单独包含清晰、可扫描的真实二维码，不得留空白框、装饰性二维码或占位图。
- 二维码目标必须是稳定的正式简报地址。当前正式地址：
  https://chenzhe223-tech.github.io/radar/daily/
- 若未来更换正式入口，必须先验证新地址可以访问、HTTPS 正常，再更新二维码。
- 每张海报生成后，必须分别解码二维码，并核对解码出的 URL 与正式简报地址完全一致。
- 还必须进行真实移动端扫码与网页访问测试；仅完成程序解码不能宣称手机扫码和线上访问已经验证。
- 不得使用未经验证的临时链接或虚构二维码。

## 5. 发布前逐张验收
每张海报均须独立检查：
- [ ] 图片是独立文件，不是拼图；画面完整，无裁切、乱码、重叠或缺失文字。
- [ ] 日期与当日正式简报一致。
- [ ] 五条精选新闻及每日 Skill 推荐准确，原文来源可追溯。
- [ ] 新闻配图与新闻主题相符，图像清晰。
- [ ] 视觉层级、对比度、留白、字号与品牌风格符合参考图。
- [ ] 第二张海报使用「今日推荐」。
- [ ] 二维码程序解码成功，且 URL 与正式简报地址一致。
- [ ] 手机扫码及打开网页的测试结果有明确记录。
- [ ] 最终交付两个独立文件，并分别提供下载入口。

## 6. 诚实报告验证状态
- 只有实际完成的检查才能标记为通过。
- 必须区分“已生成”“已解码二维码”“已进行手机扫码”“已确认线上页面可访问”等不同状态。
- 未完成的测试应明确写明“尚未验证”，不得声称发布成功或全部合格。
- 若任何 P0 项不合格，先修复再交付；不得把不合格的拼图或未经核验的海报作为最终结果。

## 7. 每次执行顺序
1. 读取当日正式简报数据与来源。
2. 确认日期、五条精选新闻、Skill 项目及正式访问地址。
3. 根据当天轮换规则选择两套参考风格。
4. 分别生成海报 A、海报 B，每张单独调用并单独保存。
5. 对两张图片逐一验收内容、版式、图片与二维码。
6. 进行可用工具支持的二维码解码和访问测试，并如实记录结果。
7. 仅交付两张独立文件，附各自链接及验证状态。
