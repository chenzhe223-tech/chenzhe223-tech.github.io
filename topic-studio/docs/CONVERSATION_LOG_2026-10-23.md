## 2. 关键对话与决策时间线

### A. 公众号内容宣传
- 用户围绕 DAVYLAB 首篇文章及后续 Dashboard Studio 贴图要求撰写推广文案，并多次要求更短、更亲近、更有行动引导。
- 确立文案风格：自然、亲民、简单，不要过度营销或像产品说明书；推广文案里的文章 URL 必须替换为真实正式文章链接。
- 首篇文章的正式标题：
  **《我用 AI 做了几个应用后，才发现：能生成，不等于能用》**
- 重要经验：设计/宣传素材要围绕用户指定的正式标题，不能擅自改成此前的替代标题。

### B. 公众号贴图与真实功能陈述
- 为 Dashboard Studio 准备公众号贴图包。文字需要亲近、易懂，避免硬性功能介绍式口吻。
- 产品介绍要准确区分当前可见的功能与仍需配置/接入的功能；预览中的演示数据不能说成真实业务数据，AI 深度分析需要配置服务，真实业务数据要单独接入并验证。
- 形成内容原则：不编造功能、不虚构用户结果、不把示意 UI 当成真实产品证据；链接必须指向正式、可访问的产品页面。

### C. 选题工作台初版与视觉问题
- 用户反馈选题发现页面布局不对称、卡片操作区错位，要求参考 Dribbble 和 Land-book 的优秀网页设计进行 UI 优化。
- 根因检查发现素材卡片的 DOM 包含视觉区、正文区、操作区，但 CSS 网格规则发生冲突，导致卡片显示不合理。
- 设计方向：排版整齐、对称、直接、高级、吸引人；保留 DAVYLAB 深海军蓝品牌识别，采用浅灰白画布、白卡片、清楚的字号层级、克制蓝色强调；不以炫技装饰牺牲可读性。
- 响应式规则：桌面端素材卡片采用“图片/视觉区—正文—操作区”三列；手机端改为图片与正文并列、操作区置于下方，不能把桌面布局硬缩进手机。

### D. 用户澄清：要在工作台素材卡片里加图，不是生成设计稿
- 用户明确纠正助手：需求是直接修改选题工作台，为每条新闻素材添加与内容匹配的图片，不是生成新的 UI 效果图。
- 当前实现逻辑：
  1. 新闻/中国 AI 动态优先读取 Davy Radar JSON 中的 `image_url`。
  2. 若没有原图，根据主题类别选择备用图片。
  3. GitHub Skill 素材使用 GitHub 项目社交预览图。
  4. 图片加载失败时自动尝试 fallback；仍失败则显示明确的图片不可用状态，不能伪称为原新闻截图。
  5. 为图片保留替代文本（alt）及图片来源/主题配图标注。
- 重要语义区别：**新闻原图**与**主题匹配的辅助配图**不是同一回事。fallback 必须标明“主题配图”，不可冒充该新闻原始配图。
- 浏览器 QA 已覆盖图片节点、HTTPS 来源、alt、fallback、桌面三列顺序与手机布局；最新相关 GitHub Browser QA 在当日运行中成功。

### E. 公众号已发内容模块
- 用户希望选题平台关联自己的微信公众号，并查看已经发表过的内容。
- 在工作台新增「公众号内容库 / 已发内容」模块，支持：
  - 查看共享文章档案与本地记录；
  - 搜索标题、摘要、栏目和链接；
  - 按栏目筛选、调整排序；
  - 手动添加/编辑/移除本地记录；
  - JSON 导入/导出；
  - 将已发文章关联到选题，关联后可把选题状态标记为“已发布”。
- 官方 API 的可用性受公众号主体、认证状态和接口权限影响；当前不能宣称工作台已直接连接微信官方 API。
- 安全决策：若后续实现官方 API，应放在 Cloudflare Worker 等服务端，AppSecret/access_token 等凭证只放服务端 Secret；绝不写入静态前端、GitHub 文件或日志。
- 备用路径：WorkBuddy 使用用户已授权的浏览器登录公众号后台，核验真实“已发表/发表记录”，更新共享 JSON；不绕过登录、验证码或平台限制。
