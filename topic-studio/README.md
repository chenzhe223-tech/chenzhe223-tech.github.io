## 增长实验室（Growth Lab）
- 目标管理：记录起始/最新订阅人数、目标日期、500 人目标与最近 10 篇阅读中位数。
- 内容实验：记录选题方向、状态、7 日阅读、分享和新增订阅；阅读达到已配置中位数 3 倍时，仅标记为内部候选线，不代表微信官方标准或爆款保证。
- 新闻贴图任务：跟踪待制作、制作中、素材验收、待交 WorkBuddy、草稿已保存、已发表和阻塞状态；后两项必须依据真实执行回执核验。
- 指标记录：手动记录订阅总人数、阅读、分享和净增订阅，支持编辑/删除、CSV 导出；至少有两条不同日期的有效订阅记录时，展示最近 14 条记录的订阅趋势图。缺失人数不会被当成 0 参与趋势或区间变化计算。
- 发布后 7 / 30 日复盘：从已发内容库选择文章，按发布后第 7 天、第 30 天分别记录真实阅读、分享和可归因新增订阅；按登记的发表日期提示到期节点，同一文章同一节点更新原记录，纳入增长 JSON 备份/导入合并和周复盘。复盘数据仍保存在当前浏览器，不会自动抓取公众号后台。
- 周复盘：导出 Markdown 周复盘，基于最近 7 天已录入的数据生成，不会把缺失数据当作 0。
- 数据迁移：支持 JSON 备份导出及导入合并；同一 ID 的导入记录覆盖本机对应记录，其他记录保留。
- 数据边界：Growth Lab 目前使用浏览器 localStorage，不提供自动跨设备同步、自动抓取微信后台指标或直接发布公众号的能力。

## 使用方式
1. 在「选题发现」顶部输入一句话，或从念头盒导出文件/粘贴灵感。
2. 连接念头盒账号后点击「分析并生成方向」；AI 服务不可用时会明确显示错误，不会展示伪造结果。
3. 选择一个方向，可继续补充调整要求。
4. 生成创作指令，复制到 ChatGPT；文章和图片需要在外部工具实际生成后再标记为完成。
5. 保存方向至选题池，并继续使用评分、筛选和排期。

## 当前集成边界（重要）
- 当前公开站点通过 GitHub Pages 静态托管，原有记录存储在当前浏览器的 localStorage，不具备账号隔离或自动跨设备同步。
- AI 选题分析通过已部署的 NianBox Cloud Worker `/ai/topic-directions` 接口进行，要求先连接念头盒账号；请求经过账号鉴权并受每用户每日次数限制。模型密钥只保留在 Worker Secret。
- 不在浏览器中直接调用模型供应商 API，不在前端代码写入 API Key。
- 念头盒支持用户主动登录后读取本人云端念头；同时保留 JSON/TXT/Markdown 文件与粘贴降级。账号令牌只保存在当前标签页 sessionStorage。
- CSS 主题封面不是生成式图片，也不代表有真实图片素材授权。
- 公众号内容库目前读取 GitHub 共享 JSON 与本地浏览器记录；只有经 WorkBuddy 从 DAVYLAB 后台核验并更新共享 JSON 后，文章才会出现在所有设备的共享列表中。当前还没有直接连接公众号官方 API。
- 官方 API 是否能直接拉取已发表内容取决于账号主体、认证情况和接口权限。任何 AppSecret/access_token 只能保存在后端 Secret，不得写入 GitHub 或前端。
- WorkBuddy 内容流水线协议和校验脚本已建立，但 WorkBuddy 本机真实下载、公众号后台录入与发布是否成功，必须基于本次实际执行的日志/回执确认。
- 不会仅因素材生成完成就自动发布；发布取决于当前内容包里可核验的明确授权范围与发布前 QA。

## 智能排期（2026-11-09）
- 文章：以「文章起排日期」作为固定锚点，此后每隔 2 天安排一篇；默认首次使用的北京时间日期为锚点，可在排期页修改；跨时区旅行和页面刷新不会改变排期节奏。
- 贴图：每周一、周三、周五、周日设置发布位；同一天可同时有文章和贴图，不互相挤占。
- 新选题创建时，默认按近 20 条专题分布做带随机性的均衡分配，写入 `columnAssignedAt` 和 `columnAssignmentMethod`；手动新建时允许修改，已存专题不随页面重载重新随机。
- 开启「新建选题自动排期」后，新选题自动进入同类型的最近空位；手动指定的日期、既有选题和导入的历史记录不被自动改写。
- 「智能填充空档」按当前状态与原有评分从未排期的选题中选择，填补未来 14 / 28 / 56 天；不会改写已有排期。
- 缺少选题的发布位展示「编辑建议 · 待核实」或来自最近 14 天 AI Radar 的「新闻线索 · 待核实」，可逐条点击「采用」加入选题池；建议不是已核验新闻，也不代表内容已创作。
- 所有排期、栏目及设置仍使用本机浏览器 localStorage，不自动发表、发送提醒、推送微信草稿箱或将 `draft` 更改为 `approved`。
- 主要实现：`topic-studio/smart-schedule.js`；集成页面：`topic-studio/index.html`。无需构建，随 GitHub Pages 主站部署。

## 选题发现 V3：页面几何与内容层级重构（2026-11-13）

- 背景：原全局布局预设将选题发现里的 AI Radar 与 XNews 当成普通 section 子卡片，在编辑 / 平衡 / Bento / 多列模式下挤成不合理的左右布局，导致文本拥挤、按钮细碎、来源层级不清。
- 本轮仅锁定「选题发现」自身的 12 栅格版式；不改变其他导航页的用户布局预设。改为「入口与导航 → AI Radar 编辑精选 → XNews 海外精选 → 深入研究工具箱」四层结构，两个来源完整分区、全宽呈现。
- 电脑大屏：来源卡片 3 列，宽度较窄的屏幕 2 列，手机端 1 列；内容工作区最大宽度约 1640px，居中并增加明确的章节间距及卡片最小留白。
